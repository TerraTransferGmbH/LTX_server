# Сервер LTX — минимальная версия: руководство по установке и эксплуатации

Версия 1.0, октябрь 2026. (C) TerraTransfer GmbH, www.terratransfer.de

## 1. Общие сведения

Минимальная версия сервера LTX — это небольшое веб-приложение на PHP, которое принимает данные
регистраторов TerraTransfer LTX по HTTP или HTTPS и сохраняет их в виде текстовых файлов, по
одному каталогу на регистратор. Защищённый паролем веб-интерфейс показывает состояние
регистраторов, экспортирует данные в CSV, строит графики и передаёт регистраторам файлы
параметров и команды.

База данных и подключение к Интернету не требуются. Сервер никогда не обращается к другим
узлам; единственный сетевой трафик — вызовы сервера регистраторами. Все данные остаются на
вашем сервере.

По сравнению с полной версией сервера LTX отсутствуют: панель с графиками, управление
пользователями, тревоги по электронной почте или SMS, передача данных в другие системы,
автоматическая очистка данных, обновление прошивки через сервер, карта.

Сами регистраторы вводятся в эксплуатацию на месте по Bluetooth с помощью веб-приложения Aquatos
Field (раздел 5); сервер только принимает их данные и передаёт файлы параметров и команды.

## 2. Требования

| Компонент | Требование |
|---|---|
| Оборудование | Linux или Windows, небольшая ВМ или одноплатный компьютер, например 1 ядро CPU, 1 ГБ ОЗУ |
| Веб-сервер | Apache 2.4 или nginx (любая версия с PHP-FPM) |
| PHP | 7.4 или новее, рекомендуется 8.x; расширения `session`, `ctype`, `iconv` (включены по умолчанию) и `gd` (графики) |
| Диск | Текстовые файлы, обычно 2–3 МБ на регистратор в год при интервале 15 минут |
| Сеть | Регистраторы обращаются к серверу по HTTP или HTTPS, порт 80 или 443 (LAN, VPN или частный APN) |
| Время | Правильное системное время (UTC); сервер передаёт своё время регистраторам при каждом сеансе связи |

Не требуются: база данных, почтовый сервер, задания cron, curl, доступ в Интернет.

## 3. Установка

Приложение состоит из трёх каталогов: `sw/` (точка входа для устройств и конфигурация),
`legacy/` (веб-интерфейс) и `docs/` (это руководство). В примерах ниже установка выполняется
в каталог `ltx` корня веб-сервера, поэтому адреса имеют вид `http://<сервер>/ltx/...`.
Можно использовать любое другое имя каталога, соответственно изменив пути.

### 3.1 Linux с Apache (Debian/Ubuntu)

```
sudo apt install apache2 php libapache2-mod-php php-gd
sudo mkdir -p /var/www/html/ltx
sudo unzip LTX_server_minimal_*.zip -d /var/www/html/        # создаёт /var/www/html/ltx
sudo mkdir -p /var/lib/ltx-data
sudo chown www-data:www-data /var/lib/ltx-data
sudo chmod 750 /var/lib/ltx-data
```

Отредактируйте `/var/www/html/ltx/sw/conf/api_key.inc.php` (раздел 4), затем перезапустите
Apache (`sudo systemctl restart apache2`). В RHEL/Rocky/Alma пакеты называются `httpd php php-gd`,
а пользователь веб-сервера — `apache`.

Если каталог данных остаётся внутри корня веб-сервера (по умолчанию `data_secret` рядом с `sw/`),
Apache должен учитывать файлы `.htaccess`: задайте `AllowOverride All` (или `AuthConfig`) для
этого каталога в виртуальном хосте. Сервер автоматически создаёт `data_secret/.htaccess` с
директивой `Require all denied`.

### 3.2 Linux с nginx

```
sudo apt install nginx php-fpm php-gd
```

Блок server (замените `php8.2-fpm` на вашу версию PHP-FPM):

```
server {
    listen 80;
    server_name ltx.example.local;
    root /var/www/html;
    index index.php;

    location ~ ^/ltx/data_secret/ { deny all; }       # только если каталог данных внутри корня веб-сервера
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
    }
}
```

Создайте каталог данных, как в п. 3.1 (пользователь `www-data`), и перезагрузите nginx.

### 3.3 Windows с XAMPP

1. Установите XAMPP (Apache + PHP 8.x) с сайта apachefriends.org.
2. Распакуйте ZIP в `C:\xampp\htdocs\` так, чтобы существовал файл
   `C:\xampp\htdocs\ltx\sw\lxu_v1.php`.
3. В файле `C:\xampp\php\php.ini` убедитесь, что строка `extension=gd` присутствует и не
   закомментирована (символ `;` удалён). Перезапустите Apache из панели управления XAMPP.
4. Создайте каталог данных, например `C:\ltx-data`, и укажите его в конфигурации как
   `C:/ltx-data` (прямые слэши).
5. Настройте запуск Apache как службы Windows (панель управления XAMPP), чтобы он запускался
   автоматически.
6. Убедитесь, что время Windows синхронизируется (регистраторы берут время с сервера).

### 3.4 HTTPS (по желанию)

Настройте HTTPS в веб-сервере обычным способом (Apache `mod_ssl`, nginx `ssl_certificate` или
обратный прокси). Регистраторы должны принимать сертификат сервера: прежде чем переводить
регистраторы на HTTPS, согласуйте с TerraTransfer, какому сертификату (публичный центр
сертификации или ваш собственный) доверяют регистраторы. Веб-интерфейс работает по HTTPS без
изменений.

## 4. Конфигурация

Все настройки находятся в файле `sw/conf/api_key.inc.php`:

| Параметр | Значение |
|---|---|
| `S_DATA` | Каталог данных. По умолчанию `../data_secret` (относительно `sw/` и `legacy/`). Рекомендуется абсолютный путь вне корня веб-сервера, например `/var/lib/ltx-data` или `C:/ltx-data`. Пользователю веб-сервера нужны права на запись. |
| `L_KEY` | Пароль веб-интерфейса. Выберите длинный пароль — это единственная защита интерфейса. |
| `D_API_KEY` | Ключ устройства. Каждый регистратор передаёт этот ключ при каждом сеансе связи. Значение согласовывается с TerraTransfer и записывается в регистраторы. |
| `DB_QUOTA` | Начальное содержимое файла `quota_days.dat` новых регистраторов (дни, строки). В этой версии только информационно. |
| `MAXM_2GM`, `MAXM_NB`, `MXGET_MEM` | Максимальный размер передачи за один сеанс для 2G/LTE-M, для LTE-NB и предел мультиблока. Оставьте значения по умолчанию, если TerraTransfer не рекомендует иное. |

Сервер отклоняет все запросы, пока в `L_KEY` или `D_API_KEY` остаётся значение-заглушка
`CHANGE_ME`.

Настройки PHP (`php.ini`): значений по умолчанию достаточно. Если вы хотите передавать на
регистратор через веб-интерфейс файлы крупнее 2 МБ, увеличьте `upload_max_filesize` и
`post_max_size`. Задайте `date.timezone = UTC`, чтобы избежать предупреждений.

## 5. Подключение регистраторов

Каждому регистратору нужны следующие настройки; они хранятся в его файле системных параметров
(`sys_param.lxp`) и обычно задаются TerraTransfer перед поставкой:

- имя хоста или IP-адрес сервера, например `ltx.example.local` или `192.168.1.10`;
- путь к точке входа для устройств: `ltx/sw/lxu_v1.php` (измените `ltx`, если установили в другой каталог);
- ключ устройства (`D_API_KEY`);
- HTTP или HTTPS, порт 80 или 443.

Сообщите эти значения TerraTransfer при заказе регистраторов или измените их самостоятельно
через веб-интерфейс (раздел 7.4, файл `sys_param.lxp`). Неверное значение в `sys_param.lxp`
отключает регистратор от сервера, поэтому изменяйте этот файл с осторожностью.

**Настройка на месте с помощью веб-приложения Aquatos Field.** Сервер не может выполнить
первоначальную настройку регистратора. Ввод в эксплуатацию и обслуживание на месте выполняются по
Bluetooth с помощью веб-приложения Aquatos Field от TerraTransfer
([aquatos-field.netlify.app](https://aquatos-field.netlify.app)): первоначальная настройка (адрес
сервера, ключ устройства, APN SIM-карты, интервалы измерения и передачи), пробные измерения,
тарирование (установка нуля) датчиков уровня, считывание памяти регистратора, самодиагностика и
отчёты в формате PDF. Приложение работает в браузере через Web Bluetooth (Chrome или Edge на
настольных компьютерах и Android, iOS через браузер Bluefy) и не требует установки. Последующие
изменения файлов параметров можно вносить и в веб-интерфейсе сервера (раздел 7.4); регистратор
применяет их при следующем сеансе связи.

Последовательность сеанса связи: регистратор вызывает
`http(s)://<сервер>/ltx/sw/lxu_v1.php?k=<ключ>&s=<MAC>` и передаёт новые данные (HTTP POST).
В ответе содержатся время сервера и ожидающие команды. С настройками по умолчанию регистратор
измеряет каждые 15 минут и связывается с сервером раз в час; оба интервала — параметры
регистратора.

## 6. Первая проверка

1. Откройте в браузере `http://<сервер>/ltx/`. Вы будете перенаправлены в веб-интерфейс.
   Войдите с паролем `L_KEY`.
2. Список устройств пуст, пока не позвонил первый регистратор. Главный журнал
   (`<S_DATA>/log/log.txt`, ссылка "Main Logfile" на стартовой странице) показывает каждый сеанс
   связи, включая отклонённые, например `(ERROR:'API Key')` при неверном ключе устройства.
3. После первого сеанса регистратор появляется в списке со своим MAC-адресом (16 шестнадцатеричных
   знаков) и именем. Откройте страницу устройства и проверьте "Last Contact" и "Files on Device".
   Первые сеансы передают список файлов и файлы параметров; данные приходят со следующей
   регулярной передачей.

## 7. Веб-интерфейс

### 7.1 Вход, гостевой режим и демо-режим

`legacy/index.php` — стартовая страница. Без входа страница работает в гостевом режиме (только
чтение) и показывает лишь регистраторы, помеченные как демонстрационные ("Enable Demo-Mode" на
стартовой странице после входа). Вход с паролем `L_KEY` даёт полный доступ; "Logout" завершает
сеанс. Страницы обновляются автоматически каждые 15–30 секунд.

### 7.2 Список устройств

Для каждого регистратора показываются MAC-адрес (ссылка на страницу устройства), имя
устройства из `iparam.lxp`, "legacy name" (произвольный текст, задаваемый на сервере), страна
мобильной сети и время последнего сеанса связи. Цвет времени последнего сеанса показывает его
давность: зелёный — менее 2 минут, светло-жёлтый — более 2 часов, жёлтый — более 4 часов,
розовый — более 12 часов, тёмно-розовый — более 24 часов, красный — более 3 дней, пурпурный —
более 14 дней.

Под списком: ссылки на главный журнал, на обозреватель файлов (только каталог данных) и на
страницу информации о PHP.

### 7.3 Страница устройства

**Device Info**: имя, legacy name, последний сеанс связи с причиной (AUTO — регулярный, MANUAL —
запущен на регистраторе, RESET, ALARM), расхождение часов регистратора, счётчики передач,
версия и дата прошивки, тип устройства, SIM (ICCID), свободная память регистратора, сигнал
мобильной сети (дБм, тип сети, страна), позиция, если регистратор её сообщает, последняя
пользовательская команда и её состояние. "Last Transmission OK" показывает последнее
подтверждение команды; `[OK]` очищает его.

**Files on Device**: каталог регистратора по состоянию на последнее сканирование. `[GET DIR]`
запрашивает новый список файлов при следующем сеансе. Для каждого файла: длина, дата и флаги на
устройстве, а также состояние локальной копии ("зеркала") на сервере: `UP-TO-DATE` означает, что
на сервере есть полный файл.

- `data.edt`: `[Open local]` — исходный текст, `[View CSV]` — преобразование в CSV в браузере,
  `[CSV(D)]` — загрузка в немецком числовом формате (запятая, точка с запятой), `[CSV(Int)]` —
  загрузка с десятичной точкой, `[CSVIEW]` — график.
- `iparam.lxp`, `sys_param.lxp`: `[Open local]` и `[Edit]` (раздел 7.4).
- `[GET(remote)]` просит регистратор передать полный файл при следующем сеансе (полезно, если
  зеркало неполное). `[DEL(remote)]` удаляет файл на регистраторе. Обе команды ставятся в очередь
  и выполняются при следующем сеансе; до этого их можно отменить.

**Cumulative data on server**: файл `out_total/total.edt` содержит всё, что сервер когда-либо
получил от этого регистратора, в порядке поступления. Доступны те же ссылки просмотра,
загрузки и графика. Используйте этот файл для архивирования и долгосрочного анализа; `data.edt` —
лишь зеркало файла на регистраторе, оно заменяется, когда регистратор начинает новый файл.

**Files to 'put'**: файлы, ожидающие передачи на регистратор (раздел 7.4), с числом попыток.
`[Remove]` отменяет передачу.

**Manage**: ссылки на журналы регистратора (сеансы связи, подключения, пользовательские
команды), "Upload Files to Device's Filesystem" (любой файл, например подготовленный файл
параметров), "Send Server Command (Byte)" и "Send User Command (Text)" (команды, определяемые
прошивкой регистратора; используйте только по указанию TerraTransfer), `[Enable DEBUG]`
(сохраняет каждую передачу в исходном виде в `dbg/`; после диагностики отключите).

### 7.4 Редактирование файлов параметров

`[Edit]` рядом с `iparam.lxp` или `sys_param.lxp` открывает форму с полем ввода для каждой строки и
кратким описанием известных полей. "Submit" помещает файл в очередь `put/`; регистратор получает
его при следующем сеансе и применяет. `iparam.lxp` содержит интервалы измерения и передачи,
описания каналов (единица измерения, число знаков, масштаб, пороги тревог) и имя устройства.
`sys_param.lxp` содержит сетевые и серверные настройки (APN, сервер, путь, ключ). Изменяйте только
те поля, значение которых вам известно; в случае сомнений обратитесь в TerraTransfer.

### 7.5 Графики (CSVIEW)

`[CSVIEW]` преобразует файл данных в CSV и строит график (требуется расширение PHP `gd`).
Флажки включают и выключают каналы, стрелки прокручивают, кнопки с лупой масштабируют,
"Export CSV" загружает показанные данные. Временные CSV-файлы хранятся в `<S_DATA>/stemp` и
автоматически удаляются через два часа.

## 8. Хранение данных

### 8.1 Структура каталогов

```
<S_DATA>/
  .htaccess                       запрет веб-доступа (Apache)
  log/log.txt, _log_old.txt       главный журнал всех сеансов связи (ротация при 100 кБ)
  stemp/                          временные CSV-файлы просмотрщика графиков
  <MAC>/                          один каталог на регистратор, 16 шестнадцатеричных знаков
    files/data.edt                зеркало файла данных регистратора (формат EDT)
    files/data.edt.bak            предыдущая версия зеркала
    files/iparam.lxp              параметры регистратора
    files/sys_param.lxp           системные параметры (сеть, сервер, ключ)
    out_total/total.edt           накопленные данные: каждый принятый фрагмент дописывается сюда
    in_new/                       фрагменты текущей передачи (сразу переносятся в total.edt)
    cmd/                          метаданные файлов устройства (*.vmeta, *.fmeta), ожидающие команды
    get/ put/ del/                очереди: файлы для получения с / передачи на / удаления на регистраторе
    dbg/                          исходные передачи при включённой отладке
    device_info.dat               состояние, записываемое при каждом сеансе (ключ/значение)
    log.txt, _log_old.txt         журнал этого регистратора (ротация при 50 кБ)
    conn_log.txt                  сведения о мобильной сети по каждому сеансу
    userio.txt                    пользовательские команды и ответы
    dapikey.dat                   ключ устройства, принятый для этого регистратора
    quota_days.dat                настройки хранения (информационно)
    user_info.dat                 legacy name, заданное в веб-интерфейсе
    date0.dat                     время первого сеанса связи
```

Все файлы текстовые, кроме исходных передач в `dbg/`.

### 8.2 Формат данных EDT

EDT ("Easy Data") — текстовый формат, UTF-8, одна запись на строку:

```
!U 0:cm 1:°C 2:us/cm 90:V(Bat) 91:°C(int) 92:%rH(int)
!1791806400 0:-43.917045 1:13.50 2:1.23 90:3.638 91:16.3 92:9.4
!+900 0:-43.917045 1:13.50 2:1.26
<NT AUTO OK(637,51,0)>
```

- `!U` — единицы измерения каналов; стоит в начале и при каждом изменении параметров.
- `!<секунды>` — измерение с абсолютной меткой времени UTC (секунды Unix), далее пары
  `канал:значение`.
- `!+<секунды>` — измерение относительно предыдущей строки.
- Каналы 0–89 — измерения, 90–99 — служебные данные регистратора (напряжение батареи,
  внутренняя температура и влажность). Строка содержит только каналы, измеренные в этот момент.
- `NoReply` вместо значения: датчик не ответил. Значение, начинающееся с `*`, превысило порог
  тревоги.
- Строки, начинающиеся с `<`, — события: `<NT AUTO OK(…)>` передача, `<NT AUTO ERROR …>`
  неудачная передача, `<RESET …>` перезапуск, `<COOKIE …>` синхронизация времени, `<NEW>` начало
  файла. После перезапуска часы регистратора начинают с нуля до следующей синхронизации; такие
  строки отображаются с датами 1970 года.
- Строки, начинающиеся с `$`, — сжатые записи; веб-интерфейс их расшифровывает.

### 8.3 Экспорт CSV

Просмотры и загрузки CSV содержат столбцы `NO` (номер строки в файле EDT), `TIME(UTC)`
(`дд.мм.гг чч:мм:сс`) и по одному столбцу на канал с именем `единица(канал)`. Отсутствующие в
строке каналы остаются пустыми. `[CSV(D)]` использует точку с запятой и десятичную запятую,
`[CSV(Int)]` — запятую и десятичную точку. Параметр URL `utc=<секунды>` сдвигает столбец
времени, например `utc=3600` для UTC+1.

## 9. Эксплуатация

**Резервное копирование**: регулярно копируйте каталог данных любым средством резервного
копирования файлов. Файлы записываются при каждом сеансе связи; копия, снятая во время сеанса,
может заканчиваться неполной последней строкой в `total.edt`, которую просмотрщик показывает как
текст; остальные данные не затрагиваются.

**Место на диске**: `out_total/total.edt` растёт без ограничения (примерно 2–3 МБ в год на
регистратор при интервале 15 минут). Для архивирования переместите или обрежьте файл между двумя
сеансами связи регистратора; следующая передача продолжится в новом файле. `stemp/` и `dbg/` можно
очищать в любое время.

**Контроль**: список устройств показывает давность последнего сеанса цветом. Регистратор, не
выходящий на связь дольше двух интервалов передачи, следует проверить (питание, SIM, сигнал).
Главный журнал показывает отклонённые сеансы, например регистратор с неверным ключом.

**Журналы**: `<S_DATA>/log/log.txt` (все сеансы, по одной строке, с результатом и временем
выполнения), `<MAC>/log.txt` (сеансы одного регистратора), `<MAC>/conn_log.txt` (сведения о
сети), `<MAC>/userio.txt` (пользовательские команды и ответы). Журналы ротируются автоматически;
предыдущая версия сохраняется как `_…_old.txt`.

**Время**: поддерживайте синхронизацию часов сервера (NTP). Регистраторы берут время сервера при
каждом сеансе; неверное время сервера даёт неверные метки времени в данных.

**Обновления**: для установки новой версии замените каталоги `sw/`, `legacy/` и `docs/`,
сохранив `sw/conf/api_key.inc.php` и каталог данных. Проверьте примечания к версии на предмет
изменённых настроек.

**Перенос на другой сервер**: установите программу на новом сервере, скопируйте каталог данных и
конфигурацию, затем измените адрес сервера в регистраторах (раздел 5) или перенаправьте старое
имя хоста. Регистраторы хранят данные до следующей успешной передачи.

## 10. Устранение неполадок

| Признак | Причина / что делать |
|---|---|
| Браузер показывает `ERROR: 'Server not configured (sw/conf/api_key.inc.php)'` | В конфигурации остались заглушки `CHANGE_ME`. |
| Регистратор не появляется, в главном журнале `(ERROR:'API Key')` | Ключ устройства в регистраторе отличается от `D_API_KEY`. |
| Регистратор не появляется, в главном журнале ничего нет | Регистратор не может связаться с сервером: проверьте имя узла/IP-адрес, путь, порт, брандмауэр, APN/VPN; проверьте настройки регистратора на месте с помощью веб-приложения Aquatos Field (раздел 5); включите отладку в регистраторе вместе с TerraTransfer. |
| Главный журнал остаётся пустым, хотя регистраторы звонят; в журнале ошибок веб-сервера предупреждения PHP `mkdir`/`fopen` … `Permission denied` | Каталог данных недоступен для записи пользователю веб-сервера или неверный путь `S_DATA`. |
| Страница устройства показывает `(no Directory Scan)` | Ещё не было полного сеанса связи или первые сеансы завершились с ошибкой. Используйте `[GET DIR]`. |
| Зеркало `data.edt` неполное (`ERROR: Real-Local`) | Используйте `[GET(remote)]`, чтобы получить весь файл при следующем сеансе. |
| `[CSVIEW]` показывает `the PHP extension 'gd' is required` | Включите `gd` в `php.ini` и перезапустите веб-сервер. |
| Вход не работает, хотя пароль верный | Сеансы PHP не сохраняются (`session.save_path` недоступен для записи) или заблокированы cookie. |
| Метки времени 1970 года | Регистратор был перезапущен и ещё не получил время сервера; исправится при следующем сеансе. |
| Каталог данных доступен из браузера | Apache: отсутствует `AllowOverride`; nginx: добавьте location с `deny all`. Лучше: вынесите каталог за пределы корня веб-сервера. |

## 11. Замечания по безопасности

- У веб-интерфейса один пароль с полными правами. Ограничьте доступ к нему (межсетевой экран,
  VPN или дополнительная аутентификация в веб-сервере), если сервер доступен из недоверенных
  сетей.
- Регистраторы передают ключ устройства при каждом сеансе. Используйте HTTPS или частную сеть
  (VPN, частный APN).
- Держите каталог данных вне корня веб-сервера или под защитой веб-сервера; в нём хранится ключ
  устройства (`dapikey.dat`).
- Своевременно обновляйте PHP и веб-сервер.
